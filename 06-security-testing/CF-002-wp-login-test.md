Observed Results
Test Condition 1 — Private/Incognito Browser

A request to:

https://jackiedesignstudio.com/wp-login.php


was made from a private/incognito browser session.

The browser displayed a Cloudflare-branded processing screen followed by:

"This has been disabled."

The normal WordPress login page was not displayed during this test.

Test Condition 2 — Existing Browser Session

The same /wp-login.php URL was accessed from a regular browser that had previously authenticated with the website.

Cloudflare performed a security check for several seconds and then the WordPress login page was displayed.

The browser had previously been configured to retain the login state on the device.

Cloudflare Security Event Evidence

Cloudflare recorded the request with the following relevant information:

Field	Observed Value
Path	/wp-login.php
Method	GET
Protocol	HTTP/2
Cache Status	None
Security Action	Mitigation
Mitigation	Managed Challenge by Custom rules
Other Suspicious Activity	None

The available Cloudflare event details did not identify the specific custom WAF rule responsible for the mitigation.

Initial Assessment

The testing confirms that Cloudflare is applying a Managed Challenge to requests for /wp-login.php.

However, the available evidence does not independently identify the specific Protect WP Login rule as the rule responsible for the event.

The different behavior between the private browser session and the existing browser session indicates that browser state, challenge state, or authentication-related state may affect the observed result.

The control will therefore remain under investigation until the behavior can be reproduced and understood consistently.

Next Steps

Repeat the test using a clean browser session.

Compare the Cloudflare event generated by each test.

Determine whether the "This has been disabled." response originates from Cloudflare or WordPress.

Verify that the intended WAF rule is responsible for the challenge.

Confirm that legitimate users can reach the WordPress login page after completing the challenge.

Document the final behavior and any required configuration changes.

Test Condition 3 — Clean Microsoft Edge Browser

A clean Microsoft Edge browser session was used to access:

https://jackiedesignstudio.com/wp-login.php


No existing authenticated browser session was used for this test.

Cloudflare displayed its security-check processing screen for several seconds.

The browser then displayed:

"This has been disabled."

The WordPress login page was not displayed.

Reproducibility

The "This has been disabled." behavior was reproduced using a clean browser session.

A previously used browser session, which retained prior authentication-related state, successfully proceeded to the WordPress login page after the Cloudflare security check.

The difference between the two test conditions has not yet been isolated to a specific cause.
